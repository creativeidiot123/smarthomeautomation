# HomeDJ architecture (single APK, local library, YouTube metadata and LAN controller)

## Ownership

- `ModeStore`: **only persisted owner** of each device's selected role. DataStore exposes `Flow<HomeDjMode?>`; null means no valid role selected. Switching roles is reversible and does not transfer server state.
- `RoleViewModel`: lifecycle-owned role loading/error state. Role changes are first-wins while DataStore saves.
- `PlaybackService : MediaLibraryService`: sole ExoPlayer, audio focus, playback queue, session and foreground-playback owner. It watches the role and stops/clears its queue outside Server mode. Trust checks remain for local Media3 controllers; no remote peer may control it.
- `ServerPlaybackViewModel`: read-only player projection and commands to the session. Connects only in Server UI; selection produces a new local audio queue, not a second player. Android's SAF document picker and persisted URI permissions are owned by `HomeDjActivity`. The Media3 queue is transient after process death.
- `YouTubePlaylistLinks`: pure, strict conversion of pasted HTTPS YouTube Music / YouTube playlist URLs to a safe playlist ID; never allows user-supplied destinations for API calls.
- `YouTubePlaylistRepository`: read-only, HTTPS YouTube Data API boundary. Maps both account-owned and explicitly imported (ID-based) playlists and playlist item responses, follows distinct pagination tokens (max 100 pages), enforces timeouts and exposes sanitized errors; no file/video downloads. The Google account is the upstream authority; the network is the only source. No persisted cache or Room owner exists.
- `SavedPlaylistStore`: single disk owner for playlist/track metadata snapshots, app-private JSON via `AtomicFile`, max 4 MB, guarded by a coroutine `Mutex`. Owned playlist refresh replaces prior owned metadata; explicit imports survive refresh. No OAuth tokens/audio stored. On explicit disconnect the snapshot is erased. The snapshot is a stale offline projection of remote YouTube metadata, not authoritative for online availability or playable media.
- `DownloadedAudioLibrary`: Android MediaStore is the authoritative source for indexed shared-storage HomeDJ audio. A user-granted media read permission permits listing only Music/HomeDJ paths, returning content URIs rather than filesystem paths. The existing Media3 service owns playback.
- `YouTubeViewModel`: only in-memory owner of a short-lived access token and account reference, and screen projection for returned metadata. Latest owned-list refresh or link import cancels prior playlist fetch and track query; selection cancels prior track query. Imported playlists live only in current UI state and are discarded when the account is reauthorized or the view resets. Playlist snapshots survive server-screen disposal/process death. Silent Google authorization is attempted when Server mode opens, with no consent UI unless the user explicitly taps Connect; a valid prior authorization triggers a metadata refresh. OAuth tokens never persist, and explicit disconnect erases metadata. Requests restart on authorized reconnect.
- `RemotePrefs`: owns one device-local server AES-256 pairing key, server opt-in flag and controller IP/key settings. All are stored in app-private preferences (backup disabled), never logged or sent as plaintext to the server; if compromised, clearing the app data revokes pairing.
- `RemoteChannel`: length-limited binary TCP transport on port 47188 with fresh 16-byte server challenges and AES-256-GCM-encrypted request and response frames. Untrusted/invalid requests fail closed. The pairing key is transferred outside the network by the user.
- `RemoteServerService`: opt-in, non-exported, connectedDevice foreground service. Single listener for private-LAN requests, checks the persisted server role and server-enabled flag before each command, and holds one local `MediaController` that forwards commands to the PlaybackService. It never creates an ExoPlayer. It closes its listener, MediaController and coroutine scope on destroy. The in-process `running` flow is status projection only, not durable truth.
- `RemoteControllerViewModel`: screen-owned poll/command loop and sole projection of remote playback state; private IPv4 addresses only. Serializes outgoing encrypted operations and cancels polling when Controller mode exits.
- `TermuxPlaylistDownloads`: validates fixed yt-dlp command arguments for a playlist ID and starts the explicit Termux RUN_COMMAND service; Termux owns execution/storage, and HomeDJ receives no completion status. No Google tokens or raw user-provided URLs are sent.
- `HomeDjActivity`: system audio picker, user-tapped Termux permission/download handoff, and Android Google authorization/revocation launchers; composes read-only UI state. Consent may require an Android IntentSender resolution. The token is passed to the ViewModel only after the YouTube read-only scope has been granted. Account association for revocation uses Google's deprecated account accessor while available; if unavailable the app clears local state and instructs user to revoke from Google Account settings.

## Trust, privacy and lifecycle

Google access tokens are sent only in Authorization headers to a fixed HTTPS Google API host. The optional Termux command uses solely a validated playlist ID; it does not receive Google credentials, account data, or HomeDJ playback authority. Tokens, account IDs and API response bodies are not logged or persisted. Playlist and track titles are persisted only in app-private metadata snapshots. API errors are shown as safe user-facing messages. There is no custom backend, stored refresh token, unattended background OAuth or background YouTube polling. The server keeps handling local playback even when the YouTube view is absent.

Switching Server to Controller is serialized via DataStore; the service observes the persisted role and stops its queue, and the Server UI disconnects its MediaController and clears its YouTube state. On failure persisting a new role, the original mode remains active. Android may kill an idle process; neither always-on remote hosting nor queue restoration is guaranteed.

Google Play services and an OAuth Android app registration for this APK's signing key are mandatory for authenticated YouTube browsing. The optional Termux handoff is independent of Google OAuth, user initiated and requires Termux permission and local setup. Its download-archive file prevents duplicate yt-dlp fetches, but download completion remains unobserved. MediaStore scan/play requires separate music read permission. Without them, local audio playback still works. The YouTube Data API metadata is not a playback/download source, and the independent Termux handoff cannot be used as proof of download success. A real-device OAuth, network and media lifecycle test remains required.

## Next boundary

Remote control now has manually entered private-LAN pairing, encrypted authenticated commands and a foreground endpoint feeding the **existing** Media3 session. It still lacks NSD discovery, QR pairing and physical-device proof; Android can kill the process. The key must be treated as sensitive. Schedules, offline storage, volume policies, persistent queue and startup/reboot behavior require their own server-owned truth and platform-specific tests. No controller playback engine or duplicate scheduling authority is to be introduced.

## Background playlist sync and temporary stream resolution

- `AutoLibraryConfig` owns opt-in device-local policy and schedules one unique 12-hour WorkManager job (unmetered network, battery-not-low). `AutoLibraryWorker` checks Server role and silent Google authorization, then refreshes account-scoped metadata into the shared `SavedPlaylistStore`. It never launches authorization UI from background.
- `SavedPlaylistStore.shared()` serializes foreground and worker JSON mutations in-process. Owned playlists are keyed by SHA-256 of the authorized account's name; account changes reset old cached metadata. Disconnect erases metadata and download choices.
- On successful refresh, the worker hands up to 20 opted-in playlist URLs to one background Termux yt-dlp run. Termux owns download lifetime and storage. A handoff is not confirmation of completion; background service start restrictions apply.
- For explicit streaming, Termux resolves a selected YouTube ID using yt-dlp `--get-url` and sends results using a one-shot mutable PendingIntent to `PlaybackService`. `StreamResolution` verifies freshness, request nonce, exit code and HTTPS GoogleVideo host; only the sole Media3 player streams. Signed URLs are neither persisted nor logged. Selecting local audio invalidates pending stream resolution.
