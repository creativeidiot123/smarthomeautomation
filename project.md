# HomeDJ project facts

- One Kotlin Android app `:app` (`dev.homedj.app`), minSdk 29, targetSdk 35, compileSdk 36, same APK on Samsung M21 and OnePlus 12.
- Gradle 8.13, AGP 8.11.1, Kotlin 2.2.20, JDK 17; Jetpack Compose/Material 3, Media3 1.8.1, DataStore 1.1.7 and WorkManager 2.11.2.
- Server mode owns one ExoPlayer in MediaLibraryService and all music files; Controller mode owns an AES-GCM paired private-LAN client (port 47188). Paired browse/track/playlist/download requests use Samsung's stored catalog; playback uses just-in-time per-song Media3 source resolution. Role persists per device. No second player.
- YouTube Data API v3 and Android Google AuthorizationClient `youtube.readonly` scope return owned/imported playlist metadata and track IDs. OAuth Android client must match app signing certificate.
- Playlist metadata is persisted app-private via bounded `SavedPlaylistStore` and is account-scoped. Tokens remain in memory; disconnect clears metadata and automatic sync selection.
- **In-app** NewPipeExtractor v0.26.5 (JitPack, GPL-3.0-or-later) independently resolves playable public, non-DRM YouTube audio streams; request headers/shape mirror NewPipe's own app (DownloaderImpl, YoutubeHttpDataSource) and visionOS-client links are preferred because no PoToken provider is installed; JDK library desugaring enabled for supported Android devices. No Termux/yt-dlp/FFmpeg needed.
- `OfflineAudioLibrary` owns original audio-only M4A/WebM/Opus app-private downloaded files, WorkManager per-song background jobs, atomic temp-file renames, 100-MiB track cap and 2-GiB aggregate cap. Playlist auto-download jobs require unmetered connectivity; in-progress transfers recheck Server role. Already downloaded audio works offline via Media3.
- `AutoLibraryWorker` refreshes playlist metadata on inexact unmetered 12-hour work and enqueues up to 150 opted-in track IDs per pass. It does not guarantee timely playback or download completion on Samsung background restrictions.
- The OnePlus Controller can explicitly request Android MediaProjection playback capture with RECORD_AUDIO permission, then send allowed stereo PCM over the existing encrypted paired TCP connection to a temporary Samsung AudioTrack output. Playback capture is not allowed for apps that deny it or DRM/calls. The cast is foreground-only, non-persistent, and its UI/service close and Wi-Fi loss terminate the stream.
- The older shared `Music/HomeDJ` MediaStore scan remains optional for legacy audio; it requires READ_MEDIA_AUDIO/READ_EXTERNAL_STORAGE and never invokes Termux. No Room database or schema change.
- GPL obligations require assessment before distributing linked APKs; neither Metrolist source nor InnerTubeX is bundled. YouTube's unofficial extraction can stop working at any time and doesn't unlock restricted content.
- Daily music schedule (Samsung only): hour slots (no midnight wrap, no overlap, at most 24) each play the cached tracks (≤500) of up to 10 library playlists, shuffled, at a STREAM_MUSIC volume. Stored in app-private `music_schedule.json` (version 1, 64 KB bound) by `ScheduleStore`. Driven by one exact alarm (`SCHEDULE_EXACT_ALARM`, user-grantable; Android 14+ fresh installs start denied) plus ``RECEIVE_BOOT_COMPLETED` re-arming on boot/update/clock change. No LAN protocol change: the OnePlus cannot edit schedules.
- Random music breaks (Samsung plays, either phone edits): off by default. Defaults are music 15–35 min (long 45–75 min, 20%), silence 10–25 min (long 30–60 min, 20%) and 5–10 s fades. Stored in SharedPreferences `homedj_music_breaks` (`settings` JSON). LAN: new `setBreaks` command plus optional `breaks`/`breakSeconds` status fields; an older Samsung answers `Unknown command` and the OnePlus shows an update hint.
- Playlist links work without a Google account: on Samsung (Library, Schedule) the extractor reads a public/unlisted playlist (≤500 songs, ≤8 pages) when no YouTube token is in memory, and the result is stored as an imported playlist in the existing JSON snapshot (no new keys). LAN: new `importPlaylist` command with a `link` field; Samsung parses and validates the link itself and replies `ok`/`message`/`id`. The OnePlus waits up to 45 s for that reply (other commands keep 5 s); an older Samsung answers `Unknown command` and the OnePlus shows an update hint.
- Physical device validation and full automatic presence control remain incomplete.
- Music-app UI modeled on Umihi Music (GPL-3.0; own implementation, no Umihi source copied): bottom navigation Home (playlist grid with a Downloaded card) / Schedule / Settings, mini player and full-screen player with seek bar and queue sheet, playlist page with download-state button, Play/Shuffle and song search, song rows with "artist • length" and a ⋮ menu. Persisted additions, all optional so older files and builds still read: `SavedPlaylistCodec` track fields `artist`/`duration` and playlist field `art` (HTTPS `*.ytimg.com` cover only); per-download `files/offline_info/<id>.json` and `files/offline_art/<id>.jpg`; WorkManager input keys `title`/`artist`/`duration`. LAN additions, all optional: status `artist`/`position`/`duration`; `tracks`/`downloads` items `artist`/`duration`; `tracks` replies `savedCount`/`savingCount`; `catalog` items `art`; commands `seek` (`position`, `index`), `cancelSave` and `removeSaved` (`id`, `kind` = `track`|`playlist`). An older Samsung answers `Unknown command` and the OnePlus shows an update hint. YouTube sync makes one extra `videos?part=contentDetails` call per 50 songs for lengths. Artwork is loaded with Coil 3.3.0 (`coil-compose`, `coil-network-okhttp`; Apache-2.0, GPL-compatible), which brings OkHttp 4.12.0 transitively and lifts kotlinx-coroutines 1.9.0→1.10.2, okio 3.4→3.15, exifinterface 1.3.6→1.4.1, profileinstaller 1.4.0→1.4.1; Compose stays on BOM 2025.09.01 (1.9.2). Icons are hand-written vector drawables in `res/drawable` from Material Icons paths (Apache-2.0); no icon library. Song art is YouTube's public `i.ytimg.com` thumbnail derived from the video ID; the OnePlus fetches thumbnails itself and shows placeholder art for Samsung's now-playing song (the status reply carries no song ID).

- Both phones show one Activity feed of recent changes (in memory on Samsung, not persisted). LAN: optional status fields `activity` (≤8 `{id, ago, source, text}`), `library` (catalog revision) and `index` (current item), and optional command fields `play` (playPause), `on` (shuffle) and `index` (next/previous); older builds ignore them and keep toggle behavior. No command, port, frame or persisted-key change.
- Paired LAN control retains one authenticated short-lived TCP request per operation (no new transport/dependency). The Controller retries after 1, 2, 4, 8, 16 and capped 30 seconds while disconnected, polls every 3 seconds when reachable (only while its UI is started), and re-polls immediately on app return, Wi-Fi availability or a failed command; one missed poll on a live link is tolerated. While remote access is on, Samsung holds a Wi-Fi lock (`WAKE_LOCK` permission) so screen-off power save does not drop paired connections. The Samsung opt-in foreground listener uses START_STICKY for Android-managed process restarts; it remains subject to OS/OEM background limits. Samsung shows its Wi-Fi IPv4 rather than a cellular/VPN address, and pairing still requires a manual private IPv4 (reserve its DHCP lease to keep it stable).

- Build/test without a Gradle wrapper: Gradle >= 8.13 (CI pins 8.13) with `--no-daemon --console=plain`; CI gate is `:app:testDebugUnitTest :app:assembleDebug`. Agent contract: `AGENTS.md` (imported by `CLAUDE.md`); skills in `.claude/skills/` mirrored to `.agents/skills/` and `.codex/.agents/skills/`.
